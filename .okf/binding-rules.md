# Vulkan binding rules

Audit truth is the vendored `scripts/khronos/vk.xml` — see the README beside
it for provenance. Layering: **ext-vulkan = Vulkan + unavoidable glue;
jovian/vulkan = PHP projection, typed handles and constants; venusian =
composition; surface = abstraction.**

## Inherited wholesale

ext-opengl's generic rules apply here without change:

- **One PHP static method = one native call.** A command binding resolves
  exactly one entry point and makes exactly one call through it. A struct-tier
  method is held to the opposite rule — **zero** resolutions, **zero** calls —
  because `pack`/`packInto`/`unpack`/`size` are flat memory work.
  `scripts/check-parity.php` enforces both halves structurally.
- The `/*@zep …*/` annotations in `src/*.h` are the single source of truth for
  the PHP surface; everything under `vulkan/` (zep) and `optimizers/` is
  generated by `scripts/gen-zep.php` and never hand-edited. **No inline C in a
  `.zep` file, ever. No FFI.**
- **Nothing silently omitted.** Anything unbindable stays as a commented
  `@reserved` line, and `bound + reserved` must equal the registry's command
  count for the class. `@audit partial <class> <reason>` sanctions a shortfall,
  never an excess.
- No error side channel. A refused call raises `E_WARNING` and returns `0` /
  void. Vulkan's own errors are `VkResult` ints, returned untouched and never
  interpreted.
- Constants live in **jovian/vulkan** as PHP enums, never in the ext. No
  `sType` is ever filled in, no extension is ever enabled, no default is ever
  supplied.
- Zephir reserved words and all-caps identifiers follow the house
  underscore/mixed-case rules in `gen-zep.php`. **No method name hits either
  rule** — every Vulkan command name and every struct name passes through
  verbatim. Several *parameter* names do (`object`, `size`, `static`, …);
  positional calls are unaffected, named arguments must use the escaped
  spelling. The escaping is `gen-zep.php`'s, applied to the annotation the
  generator wrote from the registry, so it stays in lockstep rather than being
  a list anyone maintains.

**What is different here:** `src/vk-*.{h,c}` and `src/phpvk-registry.{h,c}` are
*themselves* generated, by `scripts/gen-vk-src.php`, out of the vendored
registry. The only hand-written C is `src/phpvk-support.{h,c}`,
`src/phpvk-bridge.{h,c}` and `src/phpvk-platform.h`.

## The surface rule

One class per registry feature block, one per bound extension:

- `VK_VERSION_1_x` → `Vulkan\VK\VK1x\VK1x`. The registry splits each core
  version into internal `VK_BASE_/VK_COMPUTE_/VK_GRAPHICS_VERSION_1_x`
  sub-blocks plus the public `VK_VERSION_1_x` that depends on them; all four
  merge into one class.
- an extension → `Vulkan\Ext\<Name>\<Name>`.
- a struct or union → `Vulkan\Struct\<Name>\<Name>`.

A command belongs to the block it **first appeared in**. `vkCreateInstance` is
`VK10::vkCreateInstance` on a 1.4 loader. A command the registry declares as an
`alias` is not bound; its target is.

**Platform-conditional classes are compiled on both platforms.** The WSI and
Metal headers are pure C behind the shims in `src/phpvk-platform.h`, so
`KHRWaylandSurface` exists on the Mac and `EXTMetalSurface` exists on the Pi —
and on the wrong platform their commands simply fail to resolve and warn, the
same behaviour ext-opengl's `EGL` class has on Darwin. **There is not a single
`#ifdef` in any generated binding body.** This is a deliberate simplification
of spec §6, which described them as `#ifdef`-guarded.

## Table 1 — command parameters and returns

Applied by `scripts/gen-vk-src.php` with no per-command judgement. A type the
table does not know **stops the generator by name**.

| registry parameter | PHP | C argument |
|---|---|---|
| pointer of any depth, except a `const char *` | `int` | `(T) phpvk_arg_ptr(x)` — raw bits, 0 = NULL |
| `const char *` | `string` | `phpvk_arg_string(x)` |
| an array parameter (`const float x[4]`) | `int` | a pointer in C, so the pointer rule |
| dispatchable handle (`VkDevice`, …) | `int` | `(T) phpvk_arg_ptr(x)` |
| non-dispatchable handle (`VkImage`, …) | `int` | `(T) (uintptr_t) phpvk_arg_u64(x)` |
| `uint64_t`, `size_t`, `VkDeviceSize`, `VkDeviceAddress`, `VkFlags64` | `int` | `(T) phpvk_arg_u64(x)` |
| every other integer, every enum, every `VkFlags` bitmask | `int` | `(T) phpvk_arg_long(x)` |
| `VkBool32` | `bool` | `(VkBool32) phpvk_arg_bool(x)` |
| `float`, `double` | `double` | `(T) phpvk_arg_double(x)` |

| registry return | PHP | C |
|---|---|---|
| `void` | `void` | statement |
| `VkResult`, integers, enums | `int` | `(zend_long)` |
| `VkBool32` | `bool` | `? 1 : 0` |
| pointer, dispatchable handle, `PFN_vkVoidFunction` | `int` | `(zend_long) (uintptr_t)` |

**Non-dispatchable handles are spelled through `uintptr_t`** because
`VK_USE_64_BIT_PTR_DEFINES` makes them real pointers on every box this builds
on. The *value* still travels as a 64-bit int, so `-1` is `VK_NULL_HANDLE`'s
opposite, `UINT64_MAX`, exactly as the table promises.

## Table 2 — struct and union members

| registry member | PHP | notes |
|---|---|---|
| integer scalars, enums, `VkFlags*`, `VkDeviceSize`, `size_t`, handles | `int` | `uint64` values above `PHP_INT_MAX` wrap; pass `-1` for `VK_WHOLE_SIZE` |
| `VkBool32` | `bool` | |
| `float`, `double` | `float` | |
| `char[N]` | `string` | NUL-padded on pack, truncated at the first NUL on unpack; a string longer than `N-1` is refused by name, like a long array |
| `T[N]` of scalars | `array` of N | short arrays zero-fill; a long one is an error |
| struct or union **by value**, including `T[N]` of them | nested `array` | recursion over *inline memory only* |
| any pointer, `pNext`, `PFN_*` members, `id<MTL*>`, platform handles | `int` bits | never followed, never produced |

Missing keys pack as zero. **An unknown key is an `E_WARNING` and a refusal**,
because a typo must not silently vanish. A union's `pack` writes the members
present (last wins, in registry order); its `unpack` returns every member,
because which one is live is not knowable from the bytes. `sType` is a plain
member: the caller supplies it.

Two member shapes the table cannot express are hard generator failures naming
the member: a bit-field, and a multi-dimensional array. Neither occurs in
scope today; both exist elsewhere in the registry, which is why the generator
checks rather than assumes.

**Rule 4 applies member by member too.** `scripts/audit-registry.php`
re-reads the emitted `phpvk_fill_<T>` and `phpvk_read_<T>` bodies and requires
every member the registry declares to be written, read back and listed as an
accepted key (`structs=368 members=2296`). There is no `@audit partial` for a
member: a member the table cannot express stops the generator, so one missing
from a body can only be a mistake. `src/vk-struct-asserts.c` then carries the
generating box's `sizeof`/`offsetof` measurements into every other build as
`_Static_assert`s. See [struct-tier.md](/struct-tier.md).

## Platform scalars

`src/phpvk-platform.h` declares the WSI and Metal types itself rather than
pulling in `<wayland-client.h>`, `<xcb/xcb.h>` and `<X11/Xlib.h>`. The
generator has a matching table (`PLATFORM_TYPES` in `gen-vk-src.php`) so the
two cannot drift silently: a spelling in one and not the other stops the
generator by name. See
[traps/no-platform-dev-packages.md](/traps/no-platform-dev-packages.md).
